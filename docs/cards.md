# Карты

Классы: `Card`, `CardData`, `CardInstance`, `InstantActionEntry`/`AppliedEffectEntry`/`InstantActionKind`/`CardPropertyFlags` (`Cards/CardActions.cs`), `CardTextHelpers`, `CardPreviewDisplay`, `EffectTargetTag`, `CardType`.

Файлы: `Cards/Card.cs`, `Cards/CardData.cs`, `Cards/CardInstance.cs`, `Cards/CardActions.cs`, `Cards/CardTextHelpers.cs`, `UI/CardPreviewDisplay.cs`, `Enums/EffectTargetTag.cs`, `Enums/CardType.cs`.

См. также: [effects.md](effects.md) — точные формулы, которые считает `ComputePreviewAmount`/`Apply`; [combat-core.md](combat-core.md) — что делает `AdvanceTime`/`ResolveUpTo`, вызываемые из `Play()`; [deck-hand.md](deck-hand.md) — куда уходит `CardInstance` после розыгрыша; [enemies.md](enemies.md) — та же пара действий (`InstantActionEntry`/`AppliedEffectEntry`) на стороне `EnemyActionStep`.

## Три уровня данных одной карты

- **`CardData`** (`ScriptableObject`) — общий шаблон-ассет одной уникальной карты: `cardName`, `timeCostSeconds`, `effectDelaySeconds`, `cardType` (см. ниже), `instantActions`, `appliedEffects`, `drawCardsOnPlay`, `properties` (`CardPropertyFlags`). Один ассет на все копии карты в игре — например, один `Jab_Data` для всех Тычков.
- **`CardType`** (`Attack`/`Skill`/`Power`) — поле на `CardData`, классифицирующее карту по одной из трёх привычных для карточного рогалика категорий (атака / умение / сила). Сейчас это **чисто информационная классификация**: ни `Card`, ни `TargetSelectionManager`, ни `DeckManager` не читают `cardType` ни в одной ветке кода — оно не влияет ни на розыгрыш (`Play`/`ApplyAllEffects`), ни на текст карты, ни на то, куда карта уходит после игры (это решает `CardPropertyFlags.Exhaust`, а не `cardType`). Поле заведено заранее ради будущей категоризации (фильтры в ещё не реализованном экране колоды, иконки по типу, генератор наград по типу карты), но осознанно не обрастает логикой, которую нужно держать в голове при чтении текущего кода — YAGNI из корневого `CLAUDE.md`: место под механику зарезервировано, сама механика не пишется, пока не понадобится.
- **`CardInstance`** (`[Serializable]`, обычный C#-класс, не `ScriptableObject` и не `MonoBehaviour`) — конкретная копия карты в колоде персонажа (`DeckManager.characterDeck`, список): ссылка на `CardData` + `instanceProperties` — личные добавки поверх шаблона. `EffectiveProperties => data.properties | instanceProperties` — побитовое ИЛИ: флаги шаблона всегда действуют, флаги экземпляра могут только добавлять, никогда не снимать. Так одна конкретная копия Тычка может быть помечена Сжигаемым, пока остальные копии той же карты — нет.
- **`Card`** (`MonoBehaviour` на объекте карты в руке) — хранит `CardInstance instance`, не сырой `CardData` напрямую; `data` — read-only проброс (`instance.data`). Это тот объект, который создаёт `HandManager` в слоте руки и через который проходят клики `TargetSelectionManager`.

## Жизненный цикл `Card`

- `Awake()` — выставляет `nameLabel.text`, но только если `instance != null && instance.data != null && nameLabel != null`: `HandManager` создаёт объект через `Instantiate(cardPrefab, slots[i])` и лишь потом присваивает `instance`, а `Awake()` уже успевает отработать к этому моменту (см. «Известные грабли» в корневом `CLAUDE.md`) — без проверки здесь был бы `NullReferenceException`. Также сразу вызывает `UpdatePropertiesText()`.
- `Update()` — каждый кадр вызывает `UpdateEffectText()` (дешёвая пересборка пары строк, не завязана на какие-либо таймеры).
- `OnPointerClick` — просто `TargetSelectionManager.Instance.SelectCard(this)`; карта сама никогда не решает, нужна ли ей цель.
- `RequiresTarget` — `true`, если хоть одно действие/эффект карты помечено `EffectTargetTag.Enemy` (эффекты с тегами Player/AllEnemies клика не требуют).
- `IsValidTarget(Combatant target)` — сейчас просто `target is Enemy`: разыграть карту обратно на игрока через этот путь нельзя.
- `Play(target)` — регистрирует `OneShotEvent` на `CurrentTime + effectDelaySeconds` (приоритет `0`, побеждает тай-брейки времени — [combat-core.md](combat-core.md)), который вызовет `ApplyAllEffects(target)`; **затем** `AdvanceTime(timeCostSeconds)` и `ResolveUpTo(CurrentTime)`. Из порядка вызовов следует: если `effectDelaySeconds <= timeCostSeconds`, эффект сработает сразу же внутри этого же `Play()`; если `effectDelaySeconds` больше — событие останется висеть в расписании до тех пор, пока следующая сыгранная карта (или что-то ещё) не продвинет `ResolveUpTo` дальше нужной отметки времени. В конце уведомляет `HandManager.Instance.OnCardPlayed(this)` — карта уходит из руки и в сброс/сжигание.
- `ApplyAllEffects(chosenTarget)` — сначала **все** `instantActions` (в порядке списка карты, для каждого — по всем его целям), потом **все** `appliedEffects` (тот же порядок), и только в конце — добор `drawCardsOnPlay` карт по одной через `HandManager`. Порядок между двумя списками фиксирован (разовые действия всегда целиком отрабатывают раньше накладываемых эффектов), порядок внутри списка — порядок в инспекторе `CardData`.
- `ResolveTargets(tag, chosenTarget)`:
  - `Player` → `[combatManager.player]`;
  - `Enemy` → `[chosenTarget]`, либо пустой список, если цель не выбрана (`chosenTarget == null`, самонацеленная карта без клика);
  - `AllEnemies` → все враги из `combatManager.Enemies` с `CurrentHP > 0` — мёртвых бить нельзя даже случайно.

## Действия — `InstantActionEntry` / `AppliedEffectEntry` (`Cards/CardActions.cs`)

- **`InstantActionEntry`** — одна и та же форма `kind` (`InstantActionKind`: Damage/Block/Heal) + `amount` + `hitCount` + `targetTag`. `hitCount` — сколько раз ударить/дать блок/вылечить за один розыгрыш; каждое повторение пересчитывает модификаторы заново (см. [effects.md](effects.md) — почему это важно), не применяет их один раз к сумме.
- **`AppliedEffectEntry`** — форма `statusType` (`StatusEffectType`) + `stacks` (`float`) + `targetTag`.
- Обе сигнатуры `Apply(CombatManager, Combatant source, Combatant target)` **явно** различают, кто действует и кто получает — историческая причина: раньше `Block` всегда начислялся `source`, игнорируя `target`, пока не обобщили действие с жёстко зашитого `combatManager.player` на явный параметр (см. «Известные грабли» в корневом `CLAUDE.md`). Для `Block`/`Heal` получатель — `target ?? source` (по умолчанию себе, если цель не задана — так у карт игрока с Блоком без выбора цели; либо реальная цель, если передана — так у шагов паттерна врага, дающих блок союзнику). `Damage` такого запасного варианта не имеет — бить «в никуда» нельзя.
- `ComputePreviewAmount(source, recipient)` — используется исключительно для живого текста на карте (ниже); повторяет математику `Apply` для Damage/Block, ничего не мутирует; для Heal и default-ветки возвращает `amount` без изменений (лечение ни от чего не зависит, считать нечего).
- **`Describe(int displayValue)`** (`InstantActionEntry`) и **`Describe()`** (`AppliedEffectEntry`) — форматирование текста живёт прямо рядом с `Apply()` на том же классе, а не в отдельном классе-посреднике (раньше это были приватные `DescribeInstantAction`/`DescribeAppliedEffect` на `Card.cs`, перенесённые сюда буквально при рефакторинге). `Describe` сам не считает боевые числа — принимает уже готовое `displayValue`/использует своё поле `stacks`, разница между вызовами только в том, ОТКУДА берётся это число: `Card.UpdateEffectText()` передаёт пересчитанное под текущий бой значение (через `ComputePreviewAmount`), `CardPreviewDisplay.Show()` передаёт сырое `amount` из `CardData` (см. ниже) — сама формулировка текста («Наносит N урона всем врагам» и т. д.) от источника числа не зависит и не дублируется.
- `CardTextHelpers` (`Cards/CardTextHelpers.cs`) — то, что не привязано ни к `InstantActionEntry`, ни к `AppliedEffectEntry`, а нужно обоим (и телеграфу врага, [enemies.md](enemies.md)): `HitCountSuffix(hitCount)` (русские окончания: `1` → "", `2` → " дважды", `3–4` → " N раза", `5+` → " N раз") и `GetGenitiveName(StatusEffectType)` (родительный падеж названия эффекта — «Силы», «Слабости» и т. д.). Раньше оба метода висели статикой на `InstantActionEntry`/`AppliedEffectEntry` соответственно; вынесены в общий класс, когда стало ясно, что это чистое форматирование без привязки к конкретному действию/эффекту.
- `CardPropertyFlags` (`[Flags]`): `None`/`Exhaust`/`FrontOfDraw`, комбинируются побитово. Потребляет их только `DeckManager` ([deck-hand.md](deck-hand.md)) — на боевую математику не влияют.
- **`EffectTargetTag`** (`Player`/`Enemy`/`AllEnemies`) — словарь целей на стороне **карты**: тег висит не на карте целиком, а на каждом отдельном `InstantActionEntry`/`AppliedEffectEntry` — одна карта может, например, дать блок себе (`Player`) и одновременно наложить Слабость на кликнутого врага (`Enemy`) через два разных элемента списка. Резолвится в `Card.ResolveTargets(tag, chosenTarget)`: `Player` → всегда `combatManager.player`; `Enemy` → выбранная кликом цель, либо пустой список, если цель не выбрана; `AllEnemies` → все живые (`CurrentHP > 0`) враги из `combatManager.Enemies` на момент розыгрыша — карта не хранит фиксированное число целей и одинаково работает что при одном заспавненном враге, что при нескольких. Именно наличие хотя бы одного действия/эффекта с тегом `Enemy` на карте включает `Card.RequiresTarget` и заставляет `TargetSelectionManager` ждать клика, вместо того чтобы разыграть карту немедленно. Это отдельный enum от `EnemyActionTarget` (5 значений, [enemies.md](enemies.md)) — у карты игрока и у шага паттерна врага разные словари целей, потому что у врага есть варианты («самый слабый союзник», «конкретный индекс в списке»), бессмысленные для карты, которая всегда бьёт с одной стороны стола на другую.

## Текст на карте в руке — живой пересчёт каждый кадр/при наведении

- `UpdateEffectText()` — пересобирает `effectLabel` с нуля при каждом `Update()`. Если карта сейчас `PendingCard` у `TargetSelectionManager`, в качестве предполагаемого получателя берётся `HoveredTarget` — наведение на конкретного ослабленного/уязвимого врага мгновенно обновляет показанное число урона ещё до розыгрыша карты. Сам метод теперь только резолвит получателя и считает число (`recipient`/`ComputePreviewAmount`) — саму строку строит `action.Describe(value)`/`effect.Describe()` на объекте действия/эффекта (см. выше), `Card.cs` больше не хранит собственных приватных `DescribeInstantAction`/`DescribeAppliedEffect`/`HitCountSuffix`/`GetGenitiveName`.
- `IsPositive()` (`AppliedEffectEntry`) — `Strength`/`Regen` всегда `true`; `Toughness` — `true`, только если `stacks >= 0` (карта в теории может задать отрицательные стаки Крепкости как дебаф); всё остальное — `false`. Используется и внутри `Describe()` (различить «Даёт»/«Накладывает»), и телеграфом врага.
- `UpdatePropertiesText()` — отдельно от текста эффектов, считается один раз в `Awake` (свойства карты не меняются в течение боя): перечисляет «Сжигаемое»/«Впереди» по `instance.EffectiveProperties`.

## `CardPreviewDisplay` (`UI/CardPreviewDisplay.cs`) — статичная карточка для экранов просмотра стопок

Не несёт `Card` и вообще никакой интерактивности (ни `IPointerClickHandler`, ни ссылки на `TargetSelectionManager`) — только `Show(CardInstance instance)`, вызываемый один раз при построении списка (см. `DeckPileScreen`, [deck-hand.md](deck-hand.md)), не каждый кадр. Отличие от `Card.UpdateEffectText()` принципиальное: `Show()` передаёт в `action.Describe(action.amount)` **сырое базовое** значение прямо из `CardData`, без `ComputePreviewAmount` — то есть без пересчёта под текущего игрока/цель. Показ одной и той же карты в руке (с бонусами от Силы и т. п.) и во вкладке «Колода персонажа» (всегда база) — сознательное и единственное отличие этих двух путей форматирования, оба в итоге зовут один и тот же `Describe()`. Собран на копии `Card_Template.prefab` (`CardPreviewPrefab`) с удалённым компонентом `Card` — те же дочерние `NameLabel`/`EffectText`/`PropertiesText`, что и у карты в руке.
