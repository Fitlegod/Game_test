# Карта локации и цикл «карта → бой → карта»

Классы: `RoomType`, `MapGenerationConfig`/`RoomQuota`, `MapData`/`MapNode`/`MapEdge`, `MapGenerator`, `MapRunState`, `MapManager`, `MapScreen`/`MapScreenMode`.

Файлы: `Map/RoomType.cs`, `Map/MapGenerationConfig.cs`, `Map/MapData.cs`, `Map/MapGenerator.cs`, `Map/MapRunState.cs`, `Managers/MapManager.cs`, `UI/MapScreen.cs`; ассеты `Map/DefaultMapConfig.asset`, `Map/MapNode.prefab`; тесты `Assets/Tests/EditMode/MapGeneratorTests.cs`.

См. также: [enemies.md](enemies.md) — `EncounterManager.StartEncounter` и `EncounterData`; [combat-core.md](combat-core.md) — `CombatManager.OnVictory`/`OnDefeat`, `PlayerRunState`.

## Данные

- `RoomType` — `Start, Enemy, Elite, Event, RiskyEvent, CardMerchant, EnchantMerchant, Campfire, Chest, Boss`. Боевые: `Start`, `Enemy`, `Elite`, `Boss` (`MapNode.IsCombat`, `Map/MapData.cs:11`), остальные небоевые — пока проходимые пустышки (содержимое комнат не реализовано).
- `MapGenerationConfig` (ScriptableObject) — `quotas` (`RoomQuota`: тип, `count`, `minRow`), `extraEdgeChance` (0.3), `minFiveRows`/`maxFiveRows` (4..5), три списка энкаунтеров: `normalEncounters`, `eliteEncounters`, `bossEncounters`. `Validate()` возвращает текст ошибки, если сумма квот ≠ 84 (`FreeRoomCount`) или любой из трёх списков пуст; его вызывают `OnValidate` (→ `Debug.LogError`) и `MapGenerator.Generate` (→ `InvalidOperationException`). Ассет `DefaultMapConfig`: Enemy 33 (minRow 2), Elite 21 (5), Event 16 (2), CardMerchant 2 (2), EnchantMerchant 2 (2), RiskyEvent 10 (2); normal — `TestEncounter_1Enemy`/`_2Enemies`; elite и boss временно оба `TestEncounter_3Enemies`.
- `MapData` — `seed`, `nodes`, `edges`. `MapNode` — `id`, `row` 1..20, `col` 1..7 (у Start/Boss 4, только для отрисовки), `type`, `encounter` (только у боевых узлов). `id` узла равен его индексу в `nodes` (генератор нумерует подряд), поэтому `MapData.Node(id)` — прямой индекс.

## Генерация — `MapGenerator.Generate(seed, config)`

Статический класс, без `MonoBehaviour` и без `UnityEngine.Random`. Сид превращается в `int` собственным FNV-1a (`Fnv1a`, `Map/MapGenerator.cs:12`): `string.GetHashCode()` в .NET рандомизируется между запусками процесса и для воспроизводимости не годится. У каждого этапа свой `System.Random` с под-сидом `Fnv1a(seed + ":sizes" | ":columns" | ":edges" | ":types" | ":encounters")` (`:33-37`) — так изменение одного этапа (например, числа рёбер) не сдвигает случайные числа остальных. Все обходы — строки по возрастанию, внутри строки слева направо. Результат одного и того же сида побайтово одинаков (проверено тестом и живьём, см. ниже).

1. **Размеры строк.** Строка 1 — Start, 20 — Boss (по одному узлу, col 4). Строки 5, 12, 19 (Campfire) и 10 (Chest) — размер случайно 5..7. Остальные 14 «свободных» строк (2,3,4,6,7,8,9,11,13,14,15,16,17,18): `k` из `[minFiveRows, maxFiveRows]`, Фишер–Йетс по строкам, первым `k` — размер 5, следующим `k` — 7, остальным — 6. Сумма `5k + 7k + 6(14−2k) = 84` при любом `k` — поэтому квоты в сумме и должны давать 84.
2. **Столбцы** (`PickColumns`, `:75`). Для строки размера `n` пустых столбцов `7−n`; перебираются все маски пустых столбцов, из них отбрасываются те, где пусты одновременно {1,2} или {6,7} (`:81-82`); выбирается случайная из допустимых — без циклов «пока не повезёт». *Почему это гарантирует соседей:* у любого узла в столбце `c` для следующей строки нужен существующий узел в `{c−1,c,c+1}∩[1,7]`. В строках 2..19 размер ≥ 5, значит пустых столбцов не больше двух; тройка подряд идущих столбцов целиком пустой быть не может, а крайние окна {1,2} и {6,7} запрещены явно. Значит кандидатная пара рёбер всегда существует в обе стороны.
3. **Рёбра** (`BuildEdges`, `:93`). Start → все узлы строки 2 (`:102`), все узлы строки 19 → Boss. Для `r` от 2 до 18 кандидаты — пары (u в `r`, v в `r+1`) с `|Δcol| ≤ 1`. Каждому `u` — одно случайное ребро из его кандидатов (минимум 1 исходящее, максимум 3 — больше кандидатов не бывает); каждому `v`, оставшемуся без входящего, — одно случайное (минимум 1 входящее); каждое оставшееся кандидатное ребро — с вероятностью `extraEdgeChance` (`:126`). Рёбра — множество, дублей нет. Следствие: каждый узел достижим от Start (по индукции по строкам — у каждого есть вход из предыдущей) и из каждого узла достижим Boss (у каждого есть выход).
4. **Типы свободных комнат** (`AssignTypes`, `:131`). Строки 5/12/19 — Campfire, 10 — Chest. Квоты разворачиваются в массив 84 элементов и перемешиваются. *Проверка выполнимости до расстановки* (`:153`): для каждой строки `t` элементов с `minRow ≥ t` не больше, чем свободных комнат в строках `≥ t`; иначе `InvalidOperationException` с сидом, типами, «нужно N, есть M». Отличие от первоначального ТЗ: проверяется **каждая** `t` от 1 до 20, а не только свободные строки — `minRow` на несвободной строке (Elite/5, строка 5 — Campfire) иначе в проверку не попадал бы, а для доказательства ниже он нужен. Расстановка: по свободным комнатам в порядке обхода в каждую кладётся первый элемент массива с `minRow ≤ row` (`FindIndex`, `:165`), он удаляется. *Почему это всегда находит решение, если оно существует:* жадность ломается, только если в комнате строки `r` все оставшиеся элементы имеют `minRow > r`. Оставшихся элементов ровно столько, сколько оставшихся комнат, включая текущую, то есть не меньше `1 +` число комнат в строках `> r`; а элементов с `minRow ≥ r+1` по проверке выполнимости не больше комнат в строках `≥ r+1`. Противоречие — значит такого не случится.
5. **Энкаунтеры** (`AssignEncounters`, `:171`): Start и Enemy — случайный из `normalEncounters`, Elite — из `eliteEncounters`, Boss — из `bossEncounters`; у небоевых `null`.

## Навигация — `MapRunState`

Обычный класс (тестируется без сцены). `CurrentNodeId` (`int?`, `null` — ещё ничего не выбрано), `Visited`, `IsFinished` (выставляет `MapManager`). `GetSelectableNodes(map)`: завершённый забег — пусто; `CurrentNodeId == null` — только Start; иначе узлы, в которые ведут рёбра из текущего. `TrySelect(map, id)`: не-преемник → `false` и состояние не меняется; иначе `CurrentNodeId = id`, `Visited.Add(id)`, `true`.

## `MapManager` (`Managers/MapManager.cs`)

Поля: `config`, `seed` (пустой — случайная строка из 8 символов, логируется), `mapScreen`, `encounterManager`, `viewMapButton` (HUD-кнопка «Карта»).

- `Start()` — сбрасывает `PlayerRunState.PersistedHP = null` (новый забег), генерирует карту, создаёт `RunState`, подписывает `mapScreen.onNodeClicked` и кнопку «Карта», открывает карту в режиме выбора.
- `OnNodeClicked(id)` — игнорируется вне режима выбора (`selecting`) и при `TrySelect == false`. Боевой узел: карта закрывается, `EncounterManager.StartEncounter(node.encounter)`. Небоевой: карта перерисовывается, игрок просто переместился.
- `OnCombatEnded(victory)` — победа над Boss: `IsFinished = true`, карта с надписью «Локация пройдена», ничего не кликабельно. Иначе (победа над не-Boss или любое поражение) — карта в режиме выбора; узел поражения считается пройденным.
- Кнопка «Карта» открывает просмотр (`MapScreenMode.View`), только если не идёт выбор и забег не завершён.

## `MapScreen` (`UI/MapScreen.cs`)

Полноэкранная панель поверх всего Canvas (`MapOverlay` — последний ребёнок Canvas), вертикальный `ScrollRect`. `Show(map, run, mode)` каждый раз перестраивает содержимое с нуля. Старые дети удаляются обходом с конца (`:48`): удаление из `content` во время `foreach` по нему пропускало бы каждого второго — этот баг был найден живой проверкой и исправлен.

Режимы `MapScreenMode`: `Select` (кнопка закрытия скрыта, клики идут в `MapManager`), `View` (кнопка закрытия видна, узлы не кликабельны; бой не ставится на паузу — панель просто перекрывает ввод, как экран колод), `Finished` (надпись «Локация пройдена», ничего не кликабельно).

Отрисовка: сетка `ColSpacing=130` × `RowSpacing=100`, строка 1 внизу; рёбра — тонкие повёрнутые `Image` между центрами узлов, создаются первыми и потому лежат под узлами. Боевые узлы — иконка черепа (Enemy/Start красноватые, Elite оранжевый, Boss фиолетовый), небоевые — серые с текстом (Событие/Риск/Карты/Чары/Костёр/Сундук). Текущий узел — жёлтая обводка, посещённые — зелёная, выбираемые — белая обводка и увеличенный масштаб, остальные приглушены и не кликабельны (`Button.interactable = false`). Сид выводится в углу. Прокрутка при открытии центрируется на строке после текущей (`FocusOnCurrent`).

## Цикл «карта → бой → карта»

Запуск → `MapManager.Start` → карта (выбор, кликабелен только Start) → клик по боевому узлу → `EncounterManager.StartEncounter` → бой → `CombatManager.OnVictory`/`OnDefeat` → `EncounterManager.HandleVictory`/`HandleDefeat` (HP сохраняется / сбрасывается в `null`, участники удаляются) → `MapManager.OnCombatEnded` → карта. Победа над Boss завершает локацию; перехода на следующую нет. Поражение на самом Boss даёт тупик: у Boss нет исходящих рёбер, выбирать нечего (в ТЗ не описано, не чинилось).
